## RAG 검색 파이프라인 최적화 분석 (2026-02-20)

**현재 성능**: 700-1200ms, **목표**: 350-600ms (40-50% 개선)

### 핵심 최적화 (우선순위)

1. **벡터+FTS 병렬화** (낮음/낮음): 30-50ms → asyncio.gather
2. **IVF_FLAT 인덱스** (중간/중간): 30-50ms → brute-force 대체
3. **원문 조회 병렬화** (중간/중간): 80-150ms → async 테이블 쿼리
4. **ONNX 모델 전환** (중간/낮음): 100-200ms → PyTorch 대체
5. **쿼리 임베딩 캐싱** (낮음/낮음): 5-20ms → LRU cache

**자세한 분석**: `search-optimization-analysis.md` 참조

### 구현 순서
- Phase 1 (1주): 병렬화 + 캐싱 (50-100ms)
- Phase 2 (2주): 벡터 인덱스 + 원문 병렬화 (150-250ms)
- Phase 3 (3주): 리랭킹 최적화 (100-350ms)
- Phase 4 (4주): LLM 리라이팅 조건부 실행 (800-2400ms, 선택)
