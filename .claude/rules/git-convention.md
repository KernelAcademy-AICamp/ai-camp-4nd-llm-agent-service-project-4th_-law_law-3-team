# Git Convention Rules

Claude는 모든 Git 작업 시 이 규칙들을 **항상(ALWAYS)** 따라야 합니다.

> **상세 가이드**: `.claude/skills/project-commit/SKILL.md` 참조

## 1. 커밋 메시지 형식

```
<타입>(<범위>): <제목>

[context] <왜 이 변경이 필요했는지 1-2문장>
[changes]
- <변경 항목 1>
- <변경 항목 2>
[impact] <영향받는 모듈/레이어> (3개+ 파일 시 필수)
[files] <핵심 변경 파일 경로> (3개+ 파일 시 필수)

<꼬리말>
```

| 태그 | 필수 여부 | 설명 |
|------|----------|------|
| `[context]` | 필수 | 변경 동기/배경 |
| `[changes]` | 필수 | 변경 내용 목록 |
| `[impact]` | 3개+ 파일 | 영향 모듈/레이어 |
| `[files]` | 3개+ 파일 | 핵심 변경 파일 |

## 2. 커밋 타입

| 타입 | 설명 | 타입 | 설명 |
|------|------|------|------|
| `feat` | 새 기능 | `fix` | 버그 수정 |
| `docs` | 문서 변경 | `style` | 포맷팅만 변경 |
| `refactor` | 코드 개선 | `perf` | 성능 개선 |
| `test` | 테스트 | `build` | 빌드/의존성 |
| `ci` | CI/CD | `chore` | 기타 |

영향 태그: `BREAKING CHANGE:`, `Migration:`, `API-Change:`

## 3. 한국어 규칙

- **한국어 커밋 메시지** 사용 (타입은 영어)
- 제목 **72자 이내**, 마침표 금지
- 명령형/서술형 모두 허용 (명확성 우선)

## 4. 절대 금지

- `git push --force` (main/dev/release)
- 민감 파일 커밋 (`.env`, `*.pem`, `credentials.json`)
- 공유 브랜치에서 `reset --hard`, `rebase -i`, `amend` (push 후)
- 대용량 파일 직접 커밋 (100MB+)

## 5. 브랜치 명명

```
feature/<이슈번호>-<설명>    fix/<이슈번호>-<설명>
refactor/<설명>              docs/<설명>
release/<버전>               hotfix/<설명>
```

케밥 케이스, 소문자만. 이슈번호 없으면 생략 가능.

## 6. 커밋 체크리스트

- [ ] 하나의 논리적 단위인가?
- [ ] 메시지가 규칙을 따르는가?
- [ ] 민감 정보 미포함?
- [ ] 테스트 통과?
- [ ] 린트 에러 없음?
- [ ] 관련 CLAUDE.md 업데이트?
- [ ] 스킬/에이전트 참조 경로 확인?

## 7. 커밋 전 문서 확인

코드 변경과 문서 업데이트는 **같은 커밋**에 포함한다.

| 문서 | 확인 시점 |
|------|----------|
| `CLAUDE.md` (루트) | 아키텍처, 모듈, 환경설정 변경 |
| `backend/CLAUDE.md` | 백엔드 구조, 스크립트 변경 |
| `frontend/CLAUDE.md` | 프론트엔드 구조, API 변경 |
| 스킬/에이전트 | 코드 경로/구조 변경 |
