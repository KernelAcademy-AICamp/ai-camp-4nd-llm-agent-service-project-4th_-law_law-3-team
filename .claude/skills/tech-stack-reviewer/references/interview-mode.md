# 면접 모드 상세 가이드

사용자가 "면접", "인터뷰", "질문"을 언급하면 이 가이드를 따른다.

## 면접 질문 생성 템플릿

각 기술에 대해 3단계 질문을 생성한다:

```
## [기술명] 면접 예상 질문

### Level 1: 기본 이해
Q: "[기술]이 무엇이고, 왜 사용하나요?"
→ 모범 답변 가이드 (프로젝트 맥락 포함)

### Level 2: 프로젝트 적용
Q: "이 프로젝트에서 [기술]을 어떻게 활용했나요?"
→ 실제 코드 기반 답변 + 아키텍처 설명

### Level 3: 심화 / 트레이드오프
Q: "왜 [대안]이 아니라 [기술]을 선택했나요?"
Q: "[기술]의 한계는 무엇이고, 어떻게 개선할 수 있나요?"
→ 대안 비교 + 솔직한 한계 인정 + 개선 방향

### 꼬리 질문
면접관이 할 수 있는 후속 질문 3-5개 생성
```

## 꼬리 질문 시뮬레이션 진행 방식

1. 기술별 예상 질문을 보여준다
2. 사용자에게 "답변해볼래요?" 물어본다
3. 사용자가 답변하면:
   - 좋은 점을 먼저 짚는다
   - 빠진 키워드나 관점을 보충한다
   - 면접관이 할 수 있는 다음 꼬리 질문을 던진다
4. 사용자가 원할 때까지 반복한다

## 기술별 핵심 면접 키워드

면접 답변에 반드시 포함하면 좋은 키워드들:

| 기술 | 핵심 키워드 |
|------|-----------|
| FastAPI | 비동기(async/await), 자동 API 문서(Swagger), Pydantic 검증, 의존성 주입 |
| LangGraph | StateGraph, 노드/엣지, Command 라우팅, 체크포인터, 서브그래프 |
| RAG | 벡터 검색, BM25 하이브리드, 리랭킹, 청킹 전략, 컨텍스트 윈도우 |
| ONNX | 모델 최적화, 양자화(INT8/FP32), 추론 속도, 크로스 플랫폼 |
| Next.js | App Router, SSR/SSG/ISR, Server Components, 라우팅 |
| PostgreSQL | ACID, 인덱싱(B-tree/GIN), FTS, CTE, 파티셔닝 |
| SQLAlchemy | ORM, 세션 관리, AsyncSession, relationship, migration |
| Pydantic | 데이터 검증, Settings, BaseModel, 직렬화/역직렬화 |
| LanceDB | 벡터 인덱스(IVF_PQ), 로컬 파일 기반, 임베딩 검색 |
| MeCab | 형태소 분석, 사용자 사전(userdic), 복합명사 처리 |
| Tailwind CSS | 유틸리티 퍼스트, JIT 컴파일, 반응형, 디자인 토큰 |
| Docker | 컨테이너, 이미지 레이어, 볼륨, 멀티스테이지 빌드 |

## 면접 답변 구조 가이드 (STAR 변형)

기술 면접 답변 시 권장하는 구조:

```
1. Situation: "프로젝트에서 ~한 상황이 있었습니다"
2. Task: "~를 해결해야 했습니다"
3. Action: "~기술을 선택하여 ~방식으로 구현했습니다"
   → 실제 코드 예시 언급 (파일명, 핵심 로직)
4. Result: "결과적으로 ~한 성과를 얻었습니다"
   → 숫자로 표현 (속도, 규모, 개선폭)
```

## "왜 이걸 선택했나요?" 답변 프레임워크

대안 비교 질문에 대한 답변 구조:

```
1. 요구사항 정의: "우리 프로젝트는 ~한 특성이 있었습니다"
2. 후보 기술: "A, B, C를 검토했습니다"
3. 비교 기준: "~기준으로 평가했습니다" (성능/비용/러닝커브/생태계)
4. 선택 근거: "~이유로 A를 선택했습니다"
5. 한계 인식: "단, ~한 한계가 있고, ~로 개선할 수 있습니다"
```

이 구조로 답변하면 기술 깊이 + 의사결정 능력 + 솔직함을 모두 보여줄 수 있다.
