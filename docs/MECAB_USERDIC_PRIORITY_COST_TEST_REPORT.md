# MeCab Userdic 우선 비용(Priority Cost) 적용 테스트 리포트

> 테스트 일시: 2026-02-09
> 대상: userdic 33,981개 용어 (3자 이상 31,422개)
> 관련 문서: `docs/MECAB_USERDIC_VITERBI_ANALYSIS.md`

---

## 1. 배경 및 목적

### 1.1 문제

userdic에 등록된 법률 용어 중 **459개**가 조사(particle)와 결합될 때 MeCab Viterbi 알고리즘에 의해 잘못 분해된다.

```
단독 입력 (정상):  "저당권" → [저당권]
조사 결합 (회귀):  "저당권을" → [저당, 권, 을]   (기대: [저당권, 을])
```

근본 원인: 모든 userdic 용어를 동일 비용(cost=100)으로 등록했기 때문에,
짧은 서브 용어(`저당`, 2자)가 긴 상위 용어(`저당권`, 3자)와 동일 우선순위를 가진다.
조사가 붙으면 서브 용어 끝 글자 + 조사가 시스템 사전 단어를 형성하여 Viterbi가 잘못된 경로를 선택한다.

### 1.2 해결 전략

**대상 한정 비용 조정(Targeted Priority Cost)**:
- 회귀가 발생하는 459개 용어**만** 식별
- 해당 용어의 userdic cost를 **-3000**으로 낮춤 (나머지 33,522개는 기존 100 유지)
- 범용적 길이별 그래디언트가 아닌, 실제 회귀 데이터 기반 정밀 조정

```
기존 방식 (전체 균일):
  모든 용어 → cost=100

변경 방식 (대상 한정):
  459개 회귀 용어 → cost=-3000 (Viterbi 강력 우선)
  33,522개 정상 용어 → cost=100 (기존 유지)
```

## 2. 테스트 프로세스

### 2.1 3-Pass 빌드 사이클

```
[Pass 1] 균일 비용(100)으로 빌드 → 회귀 탐지
    ↓
    459개 회귀 용어 식별 → priority_terms.json 저장
    ↓
[Pass 2] 459개에 cost=-3000 적용하여 재빌드
    ↓
[Pass 3] 재빌드된 userdic으로 회귀 재검증
```

### 2.2 회귀 탐지 방법

1. userdic 33,981개 중 3자 이상 용어 **31,422개** 추출
2. 각 용어를 단독 입력하여 userdic MeCab 인식 확인
3. 단독 정상인 용어에 대해 **13개 조사**(`이, 가, 은, 는, 을, 의, 에, 도, 로, 와, 과, 에서, 으로`) 결합
4. 기본 MeCab과 userdic MeCab 결과 비교
5. 기본 MeCab에서 정상이지만 userdic에서 깨지는 케이스 = 회귀

### 2.3 비용 후보 테스트

두 가지 비용 수준을 테스트했다:

| 비용 | 설명 |
|------|------|
| **-3000** | 보수적 조정 (기본 cost=100 대비 -3100 차이) |
| **-10000** | 공격적 조정 (기본 cost=100 대비 -10100 차이) |

## 7. 비용 -3000 선택 근거 (왜 1~50이 아닌가)

### 7.1 일반적 권장값 (1~50)

MeCab userdic의 일반적 권장 cost는 **1~50**이다.
이 권장은 **시스템 사전에 없는 신규 단어**를 userdic에 추가할 때, 시스템 사전 단어(cost 수백~수천)와의 경쟁에서 userdic 단어가 우선되도록 하기 위한 값이다.

### 7.2 이 프로젝트에서 적용할 수 없는 이유

이 프로젝트의 회귀 문제는 **userdic 내부에서 서브 용어와 상위 용어가 경합**하는 구조다.
`저당`(2자)과 `저당권`(3자)이 **둘 다 userdic에 등록**되어 있다.

전체 userdic cost를 1~50으로 균일하게 낮춰도, 양쪽 다 같은 값으로 변경되므로 마진이 변하지 않는다.

```
현재 (cost=100 균일):
  경로 A: 저당(100) + 권 + 을  → 총 비용 -3316
  경로 B: 저당권(100) + 을     → 총 비용 -3307
                                  마진: 9  →  경로 A 선택 (회귀)

cost=10 균일로 변경:
  경로 A: 저당(10) + 권 + 을   → -3316 + 90 = -3226
  경로 B: 저당권(10) + 을      → -3307 + 90 = -3217
                                  마진: 여전히 9  →  경로 A 선택 (회귀 그대로)

cost=1 균일로 변경:
  경로 A: 저당(1) + 권 + 을    → -3316 + 99 = -3217
  경로 B: 저당권(1) + 을       → -3307 + 99 = -3208
                                  마진: 여전히 9  →  경로 A 선택 (회귀 그대로)
```

**양쪽 모두 같은 비율로 변경되면 마진(Viterbi 경로 간 비용 차이)이 보존**된다. 절대 비용을 얼마로 설정하든, 서브 용어와 상위 용어의 cost가 동일하면 회귀는 해소되지 않는다.

### 7.3 상위 용어만 선별적으로 낮춰야 하는 이유

회귀를 해소하려면 **상위 용어의 cost만 단독으로 낮춰서** 서브 용어와의 차이를 벌려야 한다.

그리고 그 차이는 **마진(connection cost에 의한 경로 간 비용 차이)을 초과**해야 한다.

```
cost=-3000 적용 (상위 용어만):
  경로 A: 저당(100) + 권 + 을    → 총 비용 -3316 (변동 없음)
  경로 B: 저당권(-3000) + 을     → -3307 - 3100 = -6407
                                    마진: -3091  →  경로 B 선택 (회귀 해소)
```

### 7.4 -3000의 산출 근거

회귀 마진 분포 (1,034건)에서 역산:

| 필요 조건 | 값 |
|----------|-----|
| 서브 용어 cost | 100 (기존 유지) |
| 상위 용어 cost | 100 - differential |
| 필요 differential | > 마진 |
| 마진 중앙값 | 3,003 |
| 마진 평균 | 3,179 |

- cost=-3000이면 differential = 100 - (-3000) = **3,100**
- 마진 3,100 미만인 케이스 = **약 90.6%** → 이 비율이 곧 해소율

| cost | differential | 해소율 | 단독 회귀 부작용 |
|------|-------------|-------|----------------|
| 50 | 50 | ~1.8% | 0개 |
| -1000 | 1,100 | ~6.9% | 0개 |
| **-3000** | **3,100** | **90.6%** | **+1개** |
| -5000 | 5,100 | ~98% | +3~5개 (추정) |
| -10000 | 10,100 | 96.1% | +8개 |

-3000은 해소율(90.6%)과 부작용(+1개)의 균형점이다.

### 7.5 대안: 서브 용어의 cost를 올리는 접근

반대로 `저당`(2자 서브 용어)의 cost를 5,000으로 올리는 방법도 이론적으로 가능하다.

```
서브 용어 cost=5000:
  경로 A: 저당(5000) + 권 + 을  → -3316 + 4900 = 1584
  경로 B: 저당권(100) + 을      → -3307
                                   경로 B 선택 (회귀 해소)
```

하지만 두 가지 문제가 있다:
1. `저당`이 **단독으로 사용되는 문맥**에서 시스템 사전과 경합하여 인식이 약화됨
2. 어떤 2자 용어가 "회귀를 일으키는 서브 용어"인지 **판별 자체가 복잡** (같은 2자 용어가 어떤 상위 용어와 경합하는지 모든 조합을 확인해야 함)

**회귀가 확인된 상위 용어만 낮추는** 접근이 판별이 단순하고 부작용이 적다.

## 8. FTS 검색 영향

### 7.1 영향 없음

세 가지 이유로 FTS 검색에 영향이 없다:

1. **인덱싱 측**: 분해맵(`decomposition_map.json`)이 복합어와 서브 토큰을 모두 FTS 인덱스에 추가
2. **검색 측**: 쿼리 토크나이징도 동일 userdic을 사용하므로 인덱싱/검색 간 일관성 유지
3. **잔여 회귀 측**: 인덱싱과 검색 양쪽에서 동일하게 분해되므로 매칭에 영향 없음

### 7.2 예시

```
인덱싱 시 "저당권" 문서:
  userdic 인식: [저당권]
  분해맵 추가:  [저당권] + [저당]
  FTS 인덱스:   "저당권 저당"

검색 시 "저당권" 쿼리:
  userdic 인식: [저당권]
  FTS 매칭:     "저당권" 히트 → 정상
```

### 10.2 잔여 회귀의 성격

43개 잔여 회귀는 **시스템 사전 단어 경합** 또는 **priority 용어 간 내부 경합**에 의한 구조적 한계다.
추가 비용 조정(cost를 더 낮춤)으로 일부 해소 가능하나, 단독 회귀 부작용이 증가하는 트레이드오프가 있다.

### 10.3 실용적 영향

- **토크나이징 품질**: 대폭 개선 (459 → 38 조사 회귀 해소)
- **하위 호환성**: `USE_MECAB_USERDIC=false`로 즉시 기존 방식 복귀 가능
