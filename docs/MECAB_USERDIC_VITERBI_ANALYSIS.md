# MeCab Userdic Viterbi 회귀 분석 및 해결 방안

> 분석 일시: 2026-02-09
> 대상: userdic 35,196개 용어 (cost=100 균일)
> 관련 문서: `docs/MECAB_USERDIC_TEST_REPORT.md`

---

## 1. 문제 요약

userdic에 등록된 법률 용어 중 **660개(22.6%)** 가 조사와 결합될 때 MeCab Viterbi 알고리즘에 의해 잘못 분해된다.

```
단독 입력 (정상):  "저당권" → [저당권]
조사 결합 (회귀):  "저당권을" → [저당, 권, 을]   (기대: [저당권, 을])
```

**근본 원인**: 모든 userdic 용어를 동일 비용(cost=100)으로 등록했기 때문에, 짧은 서브 용어(`저당`, 2자)가 긴 상위 용어(`저당권`, 3자)와 동일한 우선순위를 가진다. 조사가 붙으면 서브 용어의 끝 글자+조사가 시스템 사전 단어를 형성하여 Viterbi가 잘못된 경로를 선택한다.

---

## 2. Viterbi 비용 구조

MeCab은 **Viterbi 알고리즘**으로 입력 문장의 최적 형태소 경로를 선택한다. 총 비용이 **가장 낮은** 경로를 선택한다.

### 2.1 비용 구성 요소

| 요소 | 설명 | 결정 시점 |
|------|------|----------|
| **wcost** (word cost) | 단어 자체의 생성 비용. userdic CSV의 cost 필드 | 사전 빌드 시 |
| **connection cost** | 이전 노드 → 현재 노드 간 연결 비용. 품사 쌍에 의해 결정 | 시스템 사전의 matrix.def |
| **cumulative cost** | BOS부터 현재 노드까지의 누적 최소 비용 | Viterbi 탐색 시 |

```
총 비용 = Σ(wcost + connection cost)  (BOS → ... → EOS)
```

### 2.2 userdic vs 시스템 사전 비용 비교

| 용어 | userdic wcost | 시스템 사전 wcost | 차이 |
|------|-------------|-----------------|------|
| 저당 | 100 | 4,839 | -4,739 |
| 저당권 | 100 | 2,639 | -2,539 |
| 법정이율 | 100 | (미등재) | - |
| 소멸시효 | 100 | (복합명사 인식) | - |

> userdic cost=100은 시스템 사전 대비 매우 낮아 MeCab이 userdic 단어를 강하게 선호하게 만든다. 이것이 장점(복합명사 인식)이자 단점(서브 용어 경합)의 원인.

## 3. `저당권을` 비용 상세 분석

### 3.1 기본 MeCab (userdic 없음)

```
경로: 저당권(NNG) + 을(JKO)

  BOS → 저당권:  wcost=2639, connection=-1133  → cumul=1506
  저당권 → 을:   wcost=1109, connection=-3344  → cumul=-729
  을 → EOS:      connection=-39               → total=-768
```

### 3.2 userdic MeCab - 선택된 경로 (회귀)

```
경로: 저당(NNG,userdic) + 권(XSN) + 을(JKO)

  BOS → 저당:    wcost=100,  connection=-1133  → cumul=-1033
  저당 → 권:     wcost=1611, connection=-1901  → cumul=-1323
  권 → 을:       wcost=1109, connection=-3063  → cumul=-3277
  을 → EOS:      connection=-39               → total=-3316
```

### 3.3 userdic MeCab - 거부된 경로 (올바른 분석)

```
경로: 저당권(NNG,userdic) + 을(JKO)

  BOS → 저당권:  wcost=100,  connection=-1133  → cumul=-1033
  저당권 → 을:   wcost=1109, connection≈-3344  → cumul≈-3268
  을 → EOS:      connection=-39               → total≈-3307
```

### 3.4 경로 비교

| 경로 | 총 비용 | 선택 여부 |
|------|---------|----------|
| `저당(100)+권(1611)+을(1109)` | **-3316** | 선택됨 (비용 더 낮음) |
| `저당권(100)+을(1109)` | **-3307** | 거부됨 |

**내부 마진: 9** (= -3316 - (-3307))

두 경로 모두 userdic 단어(wcost=100)를 사용하지만, 3노드 경로(`저당+권+을`)가 2노드 경로(`저당권+을`)보다 connection cost 합산에서 9만큼 유리하여 선택된다.

### 3.5 해결에 필요한 비용 조정

`저당`의 wcost를 110 이상으로 올리면 `저당+권+을` 경로의 총 비용이 `저당권+을`보다 높아져 올바른 경로가 선택된다.

```
저당 wcost=110일 때:
  저당(110)+권+을 경로: -3316 + 10 = -3306  (10 증가)
  저당권(100)+을 경로:  -3307               (변동 없음)
  → -3306 > -3307 → 저당권+을 선택됨 ✓
```

## 5. 회귀의 근본 원인

### 5.1 메커니즘

```
                    ┌─ 서브 용어(wcost=100) ─ 접미사 ─ 조사 ─┐
용어+조사 → Viterbi ─┤                                        ├→ 비용 비교 → 낮은 쪽 선택
                    └─ 상위 용어(wcost=100) ─ 조사 ──────────┘
```

1. userdic에 `저당`(2자, wcost=100)과 `저당권`(3자, wcost=100)이 모두 등록
2. `저당권을` 입력 시 두 가지 경로가 경합:
   - 경로 A: `저당(100)` + `권(XSN)` + `을(JKO)` → 3노드
   - 경로 B: `저당권(100)` + `을(JKO)` → 2노드
3. 두 경로의 wcost 합은 비슷하지만, connection cost 차이로 경로 A가 미세하게 유리
4. Viterbi가 경로 A를 선택 → 회귀 발생

### 5.2 회귀가 발생하는 조건

모든 조건이 **동시에** 충족될 때 회귀 발생:

1. userdic에 **서브 용어**와 **상위 용어**가 모두 등록되어 있음
2. 두 용어의 **wcost가 동일** (100)
3. 서브 용어의 끝 글자 + 조사가 시스템 사전에서 **유효한 단어를 형성**
4. 해당 경로의 **총 connection cost**가 상위 용어 경로보다 낮음

### 5.3 역추출이 만드는 서브 용어 경합

`저당`이 DB에 진입한 경로:

```
원본 (법령한영사전): mortgage → "담보;저당;저당권"
역추출: 세미콜론 분리 → ["담보", "저당", "저당권"]
필터: 한글 2-10자 → 3개 모두 통과
DB 등재: 3개 모두 한영역추출(source_code="한영역추출")로 등록
userdic: 3개 모두 wcost=100으로 등록
결과: "저당"(2자)과 "저당권"(3자)이 Viterbi 경합
```

## 6. 해결 방안

### 6.1 방안 A: 길이별 비용 그래디언트 (권장)

**원리**: 짧은 용어에 높은 비용을 부여하여 Viterbi가 긴 용어를 선호하도록 유도.

**변경 위치**: `backend/scripts/build_mecab_userdic.py` → `generate_csv()`

```python
# 현재 (균일 비용)
USERDIC_COST = 100

# 변경 (길이별 비용)
def _get_cost_by_length(term: str) -> int:
    length = len(term)
    if length <= 2:
        return 5000   # 2자: 높은 비용 → 서브 토큰 경합 방지
    elif length == 3:
        return 1000   # 3자: 중간 비용
    else:
        return 100    # 4자+: 낮은 비용 → 강한 선호
```

**예상 효과**:

| 입력 | 변경 전 | 변경 후 |
|------|--------|--------|
| 저당권을 | 저당(100)+권+을 | 저당권(1000)+을 |
| 저당권의 | 저당(100)+권의 | 저당권(1000)+의 |
| 감시인도 | 감시(100)+인도 | 감시인(1000)+도 |

**마진 분석 기반 예측**:
- 마진 2,000~5,000 구간 (91.2%): 2자 용어를 5,000으로 올리면 **대부분 해결**
- 마진 0~999 구간 (1.8%): 일부 미해결 가능성

| 지표 | 값 |
|------|-----|
| 예상 해결률 | ~98% (마진 < 4,900인 케이스) |
| 2자 용어 단독 인식 | 약간 약화 (시스템 사전과 경합 시) |
| 4자+ 용어 인식 | 변화 없음 |
| 구현 난이도 | 낮음 (한 줄 변경) |

**장점**:
- 기존 용어를 제거하지 않아 커버리지 유지
- 마진 분포에 기반한 데이터 주도 접근
- 구현이 간단하고 빌드 스크립트만 수정

**단점**:
- 2자 용어의 단독 인식이 약간 약화될 수 있음
- 최적 비용값을 찾기 위한 추가 실험 필요

### 6.2 방안 B: 2자 용어 userdic 제외

**원리**: 회귀의 85.2%를 차지하는 2자 서브 토큰을 userdic에서 아예 제외.

**변경 위치**: `backend/scripts/build_mecab_userdic.py` → `generate_csv()`

```python
def generate_csv(terms: set[str], csv_path: Path) -> int:
    lines: list[str] = []
    for term in sorted(terms):
        if len(term) < 3:  # 2자 이하 제외
            continue
        # ... 기존 로직
```

**예상 효과**:

| 지표 | 값 |
|------|-----|
| 제거 용어 수 | ~7,000개 (2자 용어) |
| 회귀 해결률 | 85.2% (2자 관련만 해결) |
| 나머지 용어 | 28,196개 |
| 구현 난이도 | 매우 낮음 (조건문 한 줄) |

**장점**:
- 구현이 가장 간단
- 2자 용어는 시스템 사전에서도 대부분 인식 가능

**단점**:
- 2자 법률 용어(`계약`, `소송`, `판결` 등)의 userdic 인식 포기
- 3자 서브 토큰에 의한 14.8% 회귀는 미해결

### 6.3 방안 C: 역추출 서브 용어 필터링

**원리**: 역추출 시 상위 용어의 부분문자열인 서브 용어를 제외.

**변경 위치**: `backend/scripts/load_legal_terms_data.py` → `extract_reverse_terms()`

```python
# 같은 영어 용어에서 추출된 한글 용어들 간 부분문자열 관계 확인
# "담보;저당;저당권" → "저당"은 "저당권"의 부분문자열 → 제외
for part in parts:
    is_substring_of_longer = any(
        part != other and part in other
        for other in parts
    )
    if is_substring_of_longer:
        continue  # 서브 용어 제외
```

**예상 효과**:

| 지표 | 값 |
|------|-----|
| 제거 대상 | 역추출 서브 용어만 (~수백 개) |
| 회귀 해결률 | 부분적 (역추출 경로만 해결) |
| 구현 난이도 | 중간 (역추출 로직 수정 + DB 재로드) |

**장점**:
- 정밀 필터링으로 불필요한 서브 용어만 제거
- 다른 소스에서 등록된 용어는 유지

**단점**:
- 역추출 외 경로(법령정의사전, 생활용어사전)로 들어온 서브 용어는 미해결
- DB 재로드 + userdic 재빌드 필요
- 복잡도가 높아 유지보수 부담 증가

### 6.4 방안 비교 요약

| 항목 | A. 비용 그래디언트 | B. 2자 제외 | C. 역추출 필터 |

## 7. FTS 검색 영향도

세 가지 방안 모두 **FTS 검색에는 영향 없음**.

### 7.1 이유

분해맵(`decomposition_map.json`)이 복합어와 서브 토큰을 모두 FTS 인덱스에 추가한다.

```
"저당권" 인덱싱 시:
  userdic 인식: [저당권]
  분해맵 추가:  [저당권] + [저당]
  FTS 인덱스:   "저당권 저당"  ← 두 토큰 모두 검색 가능

"저당권" 검색 시:
  쿼리 토크나이징: [저당권] (또는 [저당, 권])
  FTS 매칭:       "저당권" 또는 "저당" 모두 히트
```

### 7.2 회귀가 FTS에 영향을 주지 않는 경우

| 시나리오 | 인덱싱 결과 | 검색 쿼리 | 매칭 |
|---------|-----------|----------|------|
| 정상 (저당권 인식) | `저당권 저당` | `저당권` | O |
| 회귀 (저당+권 분해) | `저당 권` | `저당권` → `저당 권` | O (쿼리도 동일 분해) |
| 부분 검색 | `저당권 저당` | `저당` | O (분해맵 서브 토큰) |

## 8. 참고: 단독 회귀 4개 상세

userdic 등록 후 단독 입력에서도 분해되는 용어. 조사 없이도 발생.

| 용어 | 기본 MeCab | userdic MeCab | 원인 |
|------|-----------|--------------|------|
| 부양가족 | 부양가족(NNG) | 부양(NNG)+가족(NNG) | 부양(userdic,100) + 가족(userdic,100) 경로가 부양가족(userdic,100) 경로보다 저렴 |
| 연안해 | 연안해(NNG) | 연안(NNG)+해(NNG) | 연안(userdic,100) + 해 경로 우세 |
| 영업시간 | 영업시간(NNG) | 영업(NNG)+시간(NNG) | 영업(userdic,100) + 시간(시스템사전) 경로 우세 |
| 자기거래 | 자기거래(NNG) | 자기(NNG)+거래(NNG) | 자기(시스템사전) + 거래(userdic,100) 경로 우세 |

> 이 4개는 방안 A(비용 그래디언트)로도 해결 가능: 서브 토큰의 비용을 올리면 상위 용어 경로가 유리해짐.
