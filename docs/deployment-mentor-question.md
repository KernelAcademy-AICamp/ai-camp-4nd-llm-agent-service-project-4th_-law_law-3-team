## 고민 포인트

### 1. 임베딩 모델(~2.3GB)과 백엔드 동거 문제

- 모델이 메모리에 상주하면서 백엔드 서버에 부담 (메모리 점유, 서버 시작 지연, 추론 중 API 응답 지연)
- 데이터 확장 시 임베딩 청크가 42만~90만개로 늘어나면 부담 가중
- 백엔드 스케일링 시 인스턴스마다 모델 복제 → 비용 급증

### 2. LanceDB 유지 vs Qdrant 전환

- LanceDB는 로컬 임베딩 모드(zero-infra)가 장점인데, 임베딩 모델을 분리하는 순간 이 장점이 사라집니다
- 분리 배포를 한다면 클라이언트-서버 구조로 설계된 Qdrant가 더 적합할 수 있다고 생각합니다

### 3. Neo4j 필요성

- 현재 16만 관계를 저장하고 있지만, 사용하는 쿼리가 대부분 1-2홉 조회라서 PostgreSQL로 이관 가능할 것 같습니다
- 이관하면 인프라가 줄어서 운영이 단순해집니다
