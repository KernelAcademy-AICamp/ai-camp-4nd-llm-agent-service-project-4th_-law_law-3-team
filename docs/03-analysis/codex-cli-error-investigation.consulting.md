## 외부 컨설팅 보고서

본 보고서는 Codex CLI(v0.104.0)의 기술적 결함과 이를 회피하기 위해 발생한 워크플로우 위반(FAIL-001)에 대한 조사 보고서를 External Consultant 관점에서 검증한 결과입니다.

### 1. 근본 원인 분석 검증
*   **GitHub 이슈 매칭의 정확성**: 제시된 이슈 [#11435](https://github.com/openai/codex/issues/11435)(세션 충돌)와 [#7852](https://github.com/openai/codex/issues/7852)(좀비 프로세스)는 에이전트 팀과 같은 멀티-서브프로세스 환경에서 발생하는 전형적인 **경합 조건(Race Condition) 및 자원 고갈(Resource Exhaustion)** 현상을 정확히 짚어냈습니다.
*   **상태 비저장성(Statelessness)의 간과**: 보고서는 기술적 충돌에 집중했으나, 근본적으로 Codex CLI가 CLI 도구임에도 불구하고 '사용자 편의'를 위해 도입한 **상태 유지형 아키텍처**가 자동화 파이프라인(CI/CD, Multi-agent)에서는 오히려 '독(Poison)'이 된다는 점을 명확히 규명했습니다.
*   **출력 형식 붕괴([#11122](https://github.com/openai/codex/issues/11122))**: 200줄 제한은 단순한 길이 문제가 아니라, Codex의 내부 토큰 처리 엔진이 긴 컨텍스트에서 **System Prompt(제약사항)의 우선순위를 상실**하는 현상으로 보입니다. PM의 프롬프트 간소화는 이 취약점을 본능적으로 우회한 것이나, 이는 '보안 및 절차적 투명성'을 포기한 행위입니다.

### 2. 해결방안 검증 및 추가 제안
*   **`--ephemeral` 필수화**: 가장 강력하고 즉각적인 해결책입니다. 이는 프로세스별로 격리된 메모리 공간을 강제하여 **세션 하이재킹이나 교차 오염을 방지**하는 보안 효과도 있습니다.
*   **`--full-auto` 금지**: 적절한 조치입니다. 에이전트 환경에서 `--full-auto`는 '권한 상승'과 유사한 위험을 내포하며, 특히 좀비 프로세스 발생 시 전체 시스템의 가용성(Availability)을 해칩니다.
*   **추가 대안 (Pipe Timeout 관리)**: 보고서에서 빠진 부분입니다. Codex CLI의 응답 지연 시 자식 프로세스를 강제 종료하는 **Wrapper 스크립트(또는 Task 도구의 타임아웃 명시)**가 필요합니다. 좀비 프로세스가 남지 않도록 `SIGTERM` 후 `SIGKILL`을 수행하는 정교한 핸들링이 수반되어야 합니다.

### 3. 비교 분석 검증
*   **무상태(Stateless) vs 상태기반(Stateful)**: 분석이 매우 정확합니다. Gemini CLI가 안정적인 이유는 **'Unix 철학(한 가지 일을 제대로 하고, 출력을 다음 도구로 전달)'**에 충실하기 때문입니다. 반면 Codex CLI는 'IDE의 경험'을 CLI로 옮기려다 '동시성(Concurrency)' 제어에 실패했습니다.
*   **신뢰 경계(Trust Boundary)**: Gemini CLI는 호출 시마다 컨텍스트가 초기화되므로 '이전 세션의 악의적 주입'이 불가능하지만, Codex CLI는 세션 파일이 오염될 경우 **후속 에이전트의 판단을 왜곡(Manipulation)**할 수 있는 위험이 있음을 확인했습니다.

### 4. 규칙 수정 검증
*   **200줄 제한의 현실성**: 기술적으로 타당하나, 복잡한 코드 리뷰 시에는 200줄이 부족할 수 있습니다. 따라서 '단순 제한'보다는 **'의미 단위 분할(Chunking) 후 개별 검증'** 규칙으로 고도화할 것을 권고합니다.
*   **`--full-auto` 금지의 적절성**: '수정은 오직 주 에이전트(Claude)만 수행한다'는 원칙을 강화하므로, 책임 소재를 명확히 하는 데 매우 효과적입니다.
*   **FAILURE_LOG.md 도입**: '회피(Bypass)' 행위를 '기록(Audit)'으로 전환하는 핵심적인 장치입니다. 이는 사후 분석 시 가장 먼저 참조할 **Audit Trail**이 될 것입니다.

### 5. 추가 위험 요소
*   **세션 파일 잔류 보안 위험**: `--ephemeral`을 사용하더라도 `/tmp`나 `~/.codex/`에 임시 데이터가 남을 수 있습니다. 작업 종료 후 해당 디렉토리를 명시적으로 정리하는 'Sanitization' 절차가 누락되었습니다.
*   **API Key 레이트 리밋 공유**: Gemini와 Codex를 병렬로 쓸 때, 두 도구가 동일한 백엔드 인프라를 공유한다면(예: Azure OpenAI 서비스 등), 한쪽의 과도한 호출이 다른 쪽의 거부를 유발할 수 있습니다.
*   **PM의 권한 남용(Shadow AI)**: FAIL-001 사례는 기술적 오류보다 **'인간 에이전트의 절차 무시'**가 더 큰 위험임을 보여줍니다. 규칙 위반 시 경고가 아닌 '작업 즉시 차단(Hard Block)' 기능이 에이전트 프레임워크 수준에서 고려되어야 합니다.

---
**최종 의견**: 본 조사 보고서는 기술적 근거가 탄탄하며 제시된 해결책은 합리적입니다. 다만, **'자동화된 세션 정리'**와 **'프롬프트 분할 전략'**을 보완한다면 더욱 강력한 방어 기제가 될 것입니다.
